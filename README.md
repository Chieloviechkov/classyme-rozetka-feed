# Синхронізація наявності: Хорошоп → Rozetka (ClassyMe)

Фід наявності для Rozetka, який збирається автоматично з даних сайту `classyme.com.ua` (Хорошоп).
Замість ручного файлу, який не оновлювався з 17.06.2026, Rozetka читає завжди свіжий прайс.

## Що синхронізується

Три стани, як просила замовниця — без кількостей:

| Стан на сайті | Що бачить покупець на Rozetka |
|---|---|
| В наявності | звичайна кнопка «Купити» |
| Під замовлення | кнопка «Передзамовити» + термін доставки |
| Немає в наявності / Очікується | товар знято з продажу |

Нові товари з сайту потрапляють у фід автоматично і йдуть на модерацію Rozetka.

## Як це влаштовано

```
Хорошоп: Rozetka-фід ─┐
Хорошоп: Google-фід ──┼→ сервер (cron, кожні 30 хв) → git push → GitHub
картки сайту ─────────┘                                            │
                                                                   ▼
                                              Rozetka ← Vercel (проксі, application/xml)
```

Фід збирається **на сервері, а не в хмарі**: магазин працює на платформі Cartum,
яка ріже IP дата-центрів — із Vercel уже шість запитів на секунду дають `429`.

Скелет карток (ідентифікатори, групи розмірів, характеристики, категорії з `rz_id`)
береться з еталона — знімка каталогу, який Rozetka вже прийняла. Завдяки цьому
площадка впізнає наявні картки й **не створює дублів**: відгуки та позиції зберігаються.

## Адреси

- Фід для Rozetka: `https://classyme-rozetka-feed.vercel.app/rozetka.xml?key=…`
- Той самий файл напряму: `https://raw.githubusercontent.com/Chieloviechkov/classyme-rozetka-feed/main/public/rozetka.xml`
- Статистика останньої збірки: `public/stats.json` у тому ж репозиторії

## Чому фіду можна довіряти

Джерела Хорошопа неповні й неоднакові: Rozetka-фід віддає 525 позицій, Google-фід — 446,
причому набори різні. Тому логіка побудована на трьох правилах:

1. **Відсутність товару у фіді не знімає його з продажу.** Інакше зникло б близько 140 живих позицій.
2. **Коли джерело мовчить — товар іде «під замовлення», а не «в наявності».** Продати те, чого немає, коштує дорожче: Rozetka рахує скасування з вини продавця і ховає вітрину з видачі.
3. **Позиції, про які фіди нічого не знають, дочитуються прямо з карток сайту** — сайт знає про кожен товар.

Якщо джерела підвели (порожня чи обрізана відповідь), збірка падає й **попередній фід лишається чинним** —
Rozetka просто прочитає минулу версію. Це безпечніше за публікацію неповного прайсу.

## Обслуговування

Не потребує. Cron на сервері робить усе сам, логи — у `logs/sync.log`.

Якщо знадобиться втрутитись:

```bash
ssh -p 34847 maks@194.163.136.39
cd ~/classyme-feed
./sync.sh              # зібрати й опублікувати негайно
tail -30 logs/sync.log # подивитись, що відбувалось
```

**Коли треба оновити еталон** (раз на кілька місяців, якщо на Rozetka сильно змінився каталог):
покласти свіжий знімок у `data/rozetka_old.xml` і виконати `npm run build:reference`.

## Склад

| Файл | Призначення |
|---|---|
| `lib/build-feed.mjs` | збірка XML: зіставлення з еталоном, статуси, передзамовлення |
| `lib/site-status.mjs` | читання статусів із карток сайту (обхід челенджу, щадний темп) |
| `helper/generate-feed.mjs` | те, що запускає сервер за розкладом |
| `api/rozetka.js` | проксі на Vercel: правильний Content-Type і ключ доступу |
| `scripts/build-reference.mjs` | перетворює еталонний XML на `data/reference.json` |
| `scripts/test-full.mjs` | прогін зі звіркою статусів |
| `scripts/test-negative.mjs` | перевірка, що биті джерела не потрапляють у фід |
| `scripts/verify-against-site.mjs` | звірка виданого фіда з живими картками магазину |
